# 技术说明

本文记录实现依据、格式细节和验证结果，方便以后维护或改造成别的语言对。

## 1. 为什么是「数据 mod」而不是脚本 mod

重制版（5.x）的脚本 mod 必须经 REDkit 编译，还会和 Script Merger、后续补丁互相打架。
双语字幕本质上只是「把两条文本拼成一条」，完全不需要跑代码：

- 游戏每帧都在用字符串表渲染字幕；
- 只要某个字符串 ID 的文本变成「中文 + 换行 + English」，字幕自然就双语了；
- 界面文本用的是另一批带键哈希的条目，可以完全不碰。

所以本方案没有任何 `.ws` 脚本、没有 `.reds`、不需要 REDkit，也不会因为游戏更新
（`content0` 里的脚本变化）而失效 —— 唯一会变的是字符串表的条目内容。

## 2. `.w3strings` 容器格式

全部小端。文件 = 头部 + 字符串索引块 + 键关联块 + 字符串缓冲 + 语言密钥低半。

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | `52 54 53 57` | 魔数 `"RTSW"` |
| 4 | `u32 version` | `162`/`163` = UTF-16LE 老版本；`≥164` = UTF-8（重制版为 164） |
| 8 | `u16 key_hi` | 32 位语言密钥的高 16 位 |
| 10 | `bit6 count` | 字符串条目数 |
| — | `count × 12` | 每条：`(id ^ magic, offset, length)`，offset/length 以「单元」计（UTF-8 1 字节 / UTF-16 2 字节） |
| — | `bit6 count` | 键关联条目数 |
| — | `count × 8` | 每条：`(键哈希, id ^ magic)` |
| — | `bit6 count` | 字符串缓冲的单元数（含终止符） |
| — | `bytes` | 字符串缓冲：每条「混淆后的文本 + 一个零单元」顺序排列 |
| 末 2 字节 | `u16 key_lo` | 32 位语言密钥的低 16 位 |

两条硬性要求：

1. **字符串索引块必须按 `(id ^ magic)` 升序写**。游戏对该块做二分查找；顺序错了不会崩溃，
   但界面会显示 `##key` 这类原始键名。官方文件就是这么排的，可对照验证。
2. **长度是加密密钥的一部分**，改文本必须整条重算：

```
key        = (magic >> 8) & 0xFFFF          # 注意是 bit8..23，不是高 16 位
for i in range(len_units):
    char_key = ((len_units + 1) * key) & 0xFFFF
    byte[i] ^= char_key & 0xFF              # UTF-16 还要异或 char_key >> 8
    key = rotl16(key, 1)
```

因为 `key` 每字符左旋一位、周期是 16，本实现先算出 16 个字符的掩码图案再整段重复，
用整数异或一次性完成，9.7 万条文本写盘约 1.5 秒。

### 语言密钥与混淆掩码

`magic` 由语言密钥决定，游戏发售后新增的语言（`cn`、`ua`、`ar`、`br`、`kr`、`tr`、
`esMX`）语言密钥为 0，也就是 **magic = 0，文本与 ID 全部明文**。语言只靠文件名区分。

| 语言 | 语言密钥 | magic | | 语言 | 语言密钥 | magic |
|---|---|---|---|---|---|---|
| `en` | `0x43975139` | `0x79321793` | | `ru` | `0x63481486` | `0x42386347` |
| `zh` | `0x18632176` | `0x16875467` | | `pl` | `0x83496237` | `0x73946816` |
| `de` | `0x75886138` | `0x42791159` | | `cz` | `0x24987354` | `0x21793217` |
| `fr` | `0x23863176` | `0x75921975` | | `hu` | `0x42378932` | `0x67823218` |
| `it` | `0x45931894` | `0x12375973` | | `jp` | `0x54834893` | `0x59825646` |
| `es` | `0x18796651` | `0x42387566` | | `cn` 等 | `0` | `0` |

### bit6 变长计数

```
值 < 64          → 单字节 (值 & 0x3F)
否则              → 首字节 (值 & 0x3F) | 0x40，之后每字节 7 位，
                    最高位 1 表示后继，最后一字节最高位 0
0                → 写 0x00（官方文件的写法；0x80 也能被解析成 0）
```

## 3. 哪些字符串算「字幕」

真实数据（本机 5.01）：

| 文件 | 条目 | 带键哈希 | 无键（台词） |
|---|---|---|---|
| `content/content0/en.w3strings` | 96,915 | 17,152 | 79,843 |
| `content/content0/cn.w3strings` | 97,835 | 17,123 | 80,712 |
| `content/content0/zh.w3strings` | 96,992 | 17,080 | 79,913 |

无键条目的抽样内容全部是角色对白（`'Northerners - whaddaya got against them?'`、
`'我好想、好想回到家乡'`），所以「无键 = 台词」这个判定在真实数据上成立。

`merge.py` 的 `dialogue` 模式：只合并**两边都没有键哈希**且**副语言存在同 ID** 的条目。
副语言索引取**该语言全部资源的并集**，因为 DLC 的台词 ID 常常只在
`content/content0/<副语言>.w3strings` 里有对应（本机 `DLC/dlc7/content/cn.w3strings`
的 298 条台词，295 条能在 `content0/en.w3strings` 里找到）。

## 4. mod 为什么只写改动条目

`Mods/<mod>/content/<语言>.w3strings` 会被叠加进同一语言的字符串库，按 ID 覆盖。
本机现成的第三方 mod `Mods/modfasttravelpack/content/en.w3strings` 只有 103 条、
16KB（游戏本体 7.6MB），说明字符串资源是**可增量叠加**的，不是整表替换。

因此默认 `overlay` 布局只写被合并的台词条目（约 8 万条、10MB），界面的 1.7 万条键关联
条目连字节都不会出现在 mod 里。

`mirror` 布局则对每个原版资源生成完整替换文件，语义更保守，用于排查。

## 5. 合并策略

- **分隔符**（`auto`）：整句（以 `. ! ? 。 ！ ？ ， 、 …` 等终止标点结尾，允许尾随引号）
  用 `<br>` 换行；短语用空格。`<br>` 是游戏文本控件认的换行标记（原版书籍/诗歌文本里
  大量使用）。
- **幂等**：若主语言原文已经以副语言文本结尾（旧版覆盖式 mod 的产物），跳过不叠加，
  计入 `already` 统计。
- **避免重复**：两边文本完全相同时跳过（人名、数字、专有名词），避免出现
  `Kaer Morhen Kaer Morhen`。
- **范围**：`dialogue` 只处理无键条目；`all` 额外处理两边共享同一键哈希的条目。
- **未翻译 / 近似重复**：主语言是中日韩俄乌阿时，纯 ASCII 原文（`[EN] ...` 调试串、
  `Auuugggrrrr!` 拟声词）不合并；两语言仅差标点或空白时视为同句，不合并。
- **超长过滤**：主语言原文超过 300 字符（默认）不合并 —— 书籍、怪物图鉴、任务回顾
  也在无键条目里，双起来只会撑爆面板。`--max-chars 0` 可关闭。
- **真实结果**（简中 + 英）：97,835 条中 79,219 条双语（81%），其中 77,535 条用 `<br>`
  换行、1,684 条短句用空格；跳过项：界面文本 17,123、副语言缺条目 873、同句 112、
  已是双语 88、超长 74、未翻译 346。成品 10.5MB。

## 6. 验证结果

| 项目 | 方法 | 结果 |
|---|---|---|
| 解码正确性 | 读 `en/cn/zh.w3strings`，解出的文本人工抽样 | 全部是正常台词/界面文本 |
| 编码正确性 | 解析 → 重新编码 → 与官方文件逐条比对 | 索引顺序一致、长度一致、**97,835 / 96,915 / 96,992 条密文全部一致**，缓冲单元数一致，仅「缓冲内偏移」不同（官方缓冲顺序与索引顺序不同，属实现细节） |
| 头部黄金样本 | 英语 `'A'` 单条文件的固定字节序列 | 解码/编码逐字节还原 |
| 变长计数 | 9,000 条 × 130 字符（触发多字节计数） | 回环一致 |
| 生成/安装/卸载 | 伪造同构游戏目录跑端到端 | 通过，且原版文件未被修改 |
| 幂等 | 输入「中文`<br>`English」 | 不重复叠加 |

唯一没有自动化的，是「进游戏肉眼确认字幕渲染」。`<br>` 在两行显示上是否生效，
社区同类 mod 已有实证，但仍建议第一次启动后先看一段对话。

## 7. 已知风险与备选

| 风险 | 影响 | 备选 |
|---|---|---|
| 引擎不认 `<br>` | 字幕里出现字面 `<br>` | `--sep space` |
| 文本控件高度不够 | 双行被裁 | 调小字幕字号 |
| 某些语言对内容长度差异大 | 少数台词只有单语言 | 正常损耗，统计里能看到 `缺条目` |
| 想覆盖 DLC 台词但 overlay 没生效 | DLC 台词仍单语言 | `--layout mirror` |
| 预渲染影片字幕 | 该片段仍单语言 | 需重打包 `movies.bundle` + 改 `.subs`/USM，本工具不做 |

## 8. 还能怎么扩展

- **影片字幕**：`movies.bundle` 里的 `.subs` 是文本侧车（CRLF 行、时间轴），把两种语言的
  cue 按时间轴对齐、用 `\r` 分隔即可；但必须连同完整 `.usm` 一起重新打包成
  `movies.bundle` + `metadata.store`，体积 3~4GB。
- **只翻某几类文本**：`all` 模式下再叠加键名前缀白名单（例如只处理 `panel_journal_`）。
- **导出对照表**：把 `(id, 主文本, 副文本)` 导成 CSV，可用于校对或做学习卡片。
